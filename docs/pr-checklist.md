# PR Checklist для SCC (Commercial Readiness)

## 1. Общие
- [ ] Описание изменения понятное, мотивировано и написано по стандарту.
- [ ] Номер ADR или ссылка на дизайн-документ включены (если меняется архитектура).
- [ ] Есть билд и/или скриншоты результата (при GUI изменениях).

## 2. Код качество
- [ ] Все новые функции оформлены как модули/сервисы в `services/`.
- [ ] Не используются `os.system` и `shell=True`.
- [ ] Запросы к внешним сервисам выполняются через `subprocess.run([...], check=True)`.
- [ ] Конфигурация и секреты не хардкодятся.

## 3. Безопасность
- [ ] TLS/HTTPS на всех API.
- [ ] Аутентификация через JWT / RBAC.
- [ ] Нет логирования секретов/PIN.
- [ ] Валидация входных данных (pydantic/schema + DB constraints).

## 4. Тесты
- [ ] Unit-тесты покрывают не менее 80% новых изменений.
- [ ] Интеграционные тесты для сценариев: регистрация карточки → вход → монтирование.
- [ ] Тесты на негативные случаи (SQL injection, XSS, command injection).

## 5. CI/CD
- [ ] Прогон через pre-commit: flake8/black/isort.
- [ ] Тесты выполняются в pipeline.
- [ ] Статический анализ безопасности (bandit или аналог).
- [ ] Артефакты означены и хранятся.

## 6. Документация
- [ ] Обновлён `documentation.txt` c архитектурными слоями.
- [ ] Добавлен ADR в `docs/ADR/`.
- [ ] Обновлены инструкции по развертыванию (TLS, PostgreSQL, миграции).

## 7. DevOps/SRE
- [ ] Есть playbook восстановления.
- [ ] Мониторинг настроен (метрики, alerting).
- [ ] Бэкапы БД настроены и протестированы.
